# CLAUDE.md — Summon Jump

> Working title: **Summon Jump**. 2D painted side-scrolling action RPG.
> **Ragnarok Online–style hero growth** (free farming, stats, jobs, skills, gear, cards, refine)
> + **Summoners War–style spirits and async online** (collect, runes, awaken, leader, arena vs bot-controlled defenses, daily login, missions, adventure book).
> Mobile-first (landscape), runs in the browser, shipped to stores with Capacitor. No real-time multiplayer.

Read these before any work:
- `docs/GDD.md` — game design (Thai)
- `docs/ARCHITECTURE.md` — tech stack, folders, data flow
- `docs/ROADMAP.md` — phases, scope and exit gates
- `docs/DATA_SCHEMA.md` — content tables (monsters, items, cards, spirits, skills, maps)
- `docs/ART_PIPELINE.md` — how ChatGPT-made art arrives and is processed

## 1. How we work (milestone-gated)

1. Work **one phase at a time** from `docs/ROADMAP.md`. Never start the next phase until the current phase's **Exit Gate** passes and the owner says "go".
2. At the start of a phase: read the phase section, list the tasks as a checklist in `docs/progress/PHASE_XX.md`, and confirm which **art zip** the phase needs (see §5).
3. Each phase ends with: green tests, a playable build (`npm run build && npm run preview`), an updated `docs/progress/PHASE_XX.md` (done / not done / known issues), and a short changelog entry in `CHANGELOG.md`.
4. If something in the docs is wrong or conflicts, **stop and ask** instead of guessing. Write the question in the progress file.
5. Small commits with clear messages. Never commit secrets (`.env` is git-ignored).

## 2. Stack (do not change without asking)

| Layer | Choice |
|---|---|
| Client | **Phaser 4.2.1** + **TypeScript 5.9** (strict) + **Vite 7** |
| Levels | **LDtk** files: collision grid, entity spawns, exits. Painted background layers are images, not tiles |
| Animation | Own **cut-out rig** system (`src/rig/`) driven by JSON pivot data; no paid tools required |
| Content data | **Google Sheets → CSV → `npm run content`** → typed JSON in `public/content/` |
| Shared logic | `shared/` package: formulas, damage, drops, stat calc, battle validation — used by client **and** server |
| Server (Phase 6+) | **Nakama** (self-hosted, Docker) + PostgreSQL, server runtime in **TypeScript** |
| Mobile | **Capacitor** (Android first, iOS later); PWA for web |
| Tests | Vitest (unit, shared logic), Playwright (smoke play-tests) |

## 3. Hard rules

- **Data-driven**: monsters, items, cards, spirits, skills, drops, maps live in content data, never hard-coded. Adding a monster = new CSV row + art files, zero code.
- **Shared formulas only**: damage, crit, element, stats, drop rolls and refine odds are implemented once in `shared/` and imported everywhere. No duplicate math.
- **Server-authoritative economy (from Phase 6)**: summon, drops, refine, purchases, rewards and arena results are decided or validated on the server. The client only requests.
- **Deterministic battle sim**: combat logic in `shared/sim/` uses a seeded RNG and fixed timestep so the server can re-simulate and verify (arena, world boss).
- **Mobile performance budget**: 60 fps on a mid-range Android; ≤ 150 draw calls per frame; texture atlases ≤ 2048²; WebP for art; lazy-load each zone's assets.
- **Landscape-first UI**: virtual joystick left; Attack / Jump / Skill 1–3 / Spirit buttons right; every button ≥ 56 px; safe-area aware.
- **Thai-first text**: all player-facing strings in `src/i18n/th.json` (English file kept in sync later). Fonts must support Thai.
- **No real-time multiplayer.** All online features are asynchronous (SW style).
- Keep files small (< 400 lines). One system per folder.

## 4. Feel targets (from the approved demo)

- Painted parallax zones (far / mid / near / ground strip / platforms), ambient particles per zone.
- **RO-style damage numbers**: big bold outlined numbers that pop and arc; **critical = red with yellow edge + starburst + "CRITICAL"**; weak-element = orange; resisted = grey; damage taken = pink; heal = green.
- Hit-stop on hits (35–180 ms), screen shake, additive glow VFX, enemy flash + dissolve on death.
- Spirit ultimate = cinematic: dim screen, magic circle, big spirit appears, multi-hit on all enemies.
- Normal monsters respawn when the player re-enters a map; mini-bosses on a short timer; MVPs on a long timer (RO style).
- Reference build: the single-file HTML demo (v3) — mechanics there are the baseline to port.

## 5. Art pipeline (summary — full rules in `docs/ART_PIPELINE.md`)

- All art is generated by the owner with ChatGPT from **art briefs** that Claude writes, one brief per phase, saved as `art-briefs/ART_PXX_<name>.md`.
- The owner returns **zip files** named in the brief. Put them in `art-inbox/` (git-ignored).
- Run `npm run art:import <zip>`: validates names against the brief's manifest, cleans alpha halos, trims, resizes, converts to WebP, packs atlases, writes `public/assets/<pack>/` and `src/assets/manifest.generated.ts`.
- Missing or bad files are reported in `art-inbox/REPORT.md`; write a **redo brief** listing only those files.
- **Before writing code that needs new art, write the art brief first** and tell the owner. Use placeholder shapes until the zip arrives; never block on art.

## 6. Commands (set up in Phase 0)

```
npm run dev            # client dev server
npm run build          # production build
npm run test           # vitest
npm run e2e            # playwright smoke tests
npm run content        # CSV -> JSON content build + validation
npm run levels         # tools/levels/rooms.ts -> levels/world.ldtk (+ public/levels/)
npm run balance        # route simulation -> docs/BALANCE.md (time to MVP, kill times)
npm run art:import -- <zip> --brief art-briefs/ART_PXX.md   # import a ChatGPT art zip
npm run server:up      # docker compose up nakama + postgres (Phase 6+)
```

## 7. Definition of done (every task)

- Typecheck passes, lint passes, tests pass.
- Works on a 390×844 phone in landscape and on desktop with keyboard.
- No console errors in a 5-minute play session.
- Strings are in i18n files; numbers come from content data.
