# Architecture — Summon Jump

## 1. Repository layout

```
summon-jump/
├─ CLAUDE.md
├─ docs/                    # GDD, roadmap, schema, art pipeline, progress/
├─ art-briefs/              # ART_PXX_*.md briefs sent to ChatGPT (committed)
├─ art-inbox/               # zips from ChatGPT (git-ignored) + REPORT.md
├─ content/                 # CSV exported from Google Sheets (committed)
│   ├─ monsters.csv  items.csv  cards.csv  spirits.csv  skills.csv
│   ├─ jobs.csv  drops.csv  maps.csv  runes.csv  quests.csv  i18n_th.csv
├─ levels/                  # LDtk project + per-map .ldtk files
├─ shared/                  # pure TS, no Phaser, no DOM — used by client and server
│   ├─ formulas/            # stats, damage, crit, element, refine, exp curve
│   ├─ sim/                 # deterministic combat sim (seeded RNG, fixed 60Hz step)
│   ├─ content/             # generated types + loaders for content JSON
│   └─ rules/               # drops, summon odds, arena scoring, reward tables
├─ src/                     # Phaser client
│   ├─ boot/                # preload, asset manifest, zone pack loader
│   ├─ scenes/              # Title, World, Arena, Dungeon, UI overlay
│   ├─ world/               # rooms, LDtk loader, collision, exits, respawn timers
│   ├─ actors/              # hero, enemies (behaviour tree / state machine), spirits
│   ├─ rig/                 # cut-out rig runtime + pose clips (JSON)
│   ├─ combat/              # hitboxes, hit-stop, skills runtime (calls shared/)
│   ├─ vfx/                 # particles, additive sprites, damage numbers
│   ├─ ui/                  # HUD, touch controls, menus (DOM overlay or Phaser UI)
│   ├─ net/                 # Nakama client wrapper (Phase 6+)
│   ├─ save/                # local save (pre-server) + cloud sync
│   ├─ i18n/                # th.json, en.json
│   └─ assets/manifest.generated.ts
├─ public/
│   ├─ content/*.json       # generated by `npm run content`
│   └─ assets/<pack>/       # generated by `npm run art:import` (WebP + atlases)
├─ server/                  # Nakama TypeScript runtime modules (Phase 6+)
│   ├─ src/rpc/             # economy RPCs: summon, refine, claim, arena
│   ├─ src/jobs/            # season reset, world boss rotation, daily reset
│   └─ docker-compose.yml   # nakama + postgres
├─ tools/
│   ├─ content-build.ts     # CSV -> JSON + validation (ids, refs, ranges)
│   └─ art-import/          # zip -> validate -> clean -> webp -> atlas -> manifest
└─ tests/                   # vitest (shared), playwright (smoke)
```

## 2. Data flow

```
Google Sheets ──export CSV──▶ content/*.csv ──npm run content──▶ public/content/*.json + shared/content/types.ts
ChatGPT ──zip──▶ art-inbox/ ──npm run art:import──▶ public/assets/<pack>/ + manifest.generated.ts
LDtk editor ──▶ levels/*.ldtk ──loaded at runtime──▶ collision, spawns, exits, background layer refs
```

- Content JSON is versioned (`contentVersion`). From Phase 6 the server serves the current content bundle so balance fixes and new monsters ship **without a store update**.

## 3. Client runtime

- **Scenes:** `Boot → Title → World (+UI overlay)`; `Arena`, `Dungeon` and `Tower` reuse World systems with different rules.
- **Room model:** each map = LDtk level (collision IntGrid 16 px, entities: spawns, NPCs, exits, gates, objects) + art layers `far/mid/near/ground/platforms` from the zone pack.
- **Respawn rules:** normal monsters respawn on room re-entry; mini-bosses and MVPs use timestamps in the save (`respawnAt`).
- **Actors:** finite-state machine per actor (`idle, patrol, chase, windup, attack, recover, hurt, dead`). Behaviour params come from `monsters.csv` (`ai` column + numbers). Bosses have scripted phase tables.
- **Hero rig:** parts + pivots JSON per job/armor set; clips (`idle, run, jump, fall, attack1-3, skill_*, hurt, cast`) are keyframe JSON interpreted by `src/rig`.
- **Monster animation (cheap, scalable):** 3–4 painted poses per monster (`idle`, `windup`, `attack`, `hurt`) + code tweens (squash, lunge, bob). Bosses can use full cut-out rigs.
- **Combat:** hitboxes are authored per clip; damage → `shared/formulas.damage()`; results feed VFX, numbers, hit-stop.

## 4. Server (Phase 6+) — Nakama

| Feature | Nakama building block |
|---|---|
| Accounts | Device / Google / Apple auth, account linking |
| Save & inventory | Storage objects (server-write-only for economy collections) |
| Economy | RPCs: `summon`, `refine`, `socketCard`, `claimDaily`, `claimMission`, `buyShop` — all rolls on the server with `shared/rules` |
| Drops | Client sends a **battle report** (seed, kills, duration, inputs hash); server checks plausibility with `shared/sim` limits, then grants drops |
| Arena | Defense snapshot stored per player; matchmaking by rating bands via storage queries; attack = client plays vs bot, submits input log; server re-sims (deterministic) or plausibility-checks, then updates rating and leaderboard |
| Leagues / seasons | Leaderboards + tournaments with reset schedules |
| Guilds | Groups + group storage; guild war = async attacks on stored defenses |
| World boss | Tournament leaderboard (damage sum), 3 attempts/day via storage counters |
| Mail, daily, missions | Storage + notifications; daily reset job at 05:00 ICT |
| Chat (optional) | Group chat channels |

Hosting: one VPS (4 GB RAM) with Docker Compose (nakama + postgres), nightly DB backup, Cloudflare in front for the static client.

## 5. Anti-cheat stance

- Never trust client currency, items, or rolls.
- Battle reports are bounded: max damage per second from `shared/sim` caps, minimum clear times, kill counts vs room spawn tables.
- Arena: input-log re-simulation (target), plausibility check (MVP of feature).

## 6. Performance

- Zone packs loaded on demand (~3–6 MB WebP per zone); atlases per pack.
- Damage numbers and particles from object pools.
- Additive VFX use WebGL blend modes; Canvas fallback not required.
