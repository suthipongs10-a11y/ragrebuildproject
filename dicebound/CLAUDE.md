# CLAUDE.md — DICEBOUND

ไฟล์นี้คือ single source of truth ของโปรเจกต์ อ่านให้จบก่อนเริ่มงานทุก session
แล้วอ่าน `STATUS.md` ต่อเพื่อดูว่างานค้างอยู่ที่ไหน คุยกับเจ้าของโปรเจกต์เป็นภาษาไทย กระชับ

---

## 1. เกมนี้คืออะไร

**DICEBOUND** — roguelike auto-battler ที่ใช้ลูกเต๋าเดินบนกระดานวนรอบ (แบบเกมเศรษฐี) แทนสล็อต
ผู้เล่นทอยเต๋า เดินตกช่อง ได้ผลของช่อง อัปช่อง จัดกระดาน ส่วนทีมสู้มอนอัตโนมัติ

- **เป้าหมาย:** วางขายบน Steam (PC: Windows ก่อน, ต้องเล่นบน Steam Deck ได้) แบบจ่ายครั้งเดียว ไม่มีกาชา ไม่มีโฆษณา
- **จอ:** แนวนอน 16:9 เป็นหลัก — กระดานซ้าย ~40%, ฉากต่อสู้ขวา ~60% (ตาม mockup แนวนอน)
- **1 รัน:** 10 รอบกระดาน ≈ 20–25 นาที, 3 Act + บอสใหญ่

### Design pillars (ใช้ตัดสินทุกฟีเจอร์ ถ้าไม่ช่วยข้อไหนเลยให้ตัดทิ้ง)
1. **ลุ้นทุกทอย** — ในระยะ 1–6 ช่องต้องมีทั้งช่องที่อยากได้และช่องที่อยากเลี่ยงเสมอ
2. **แผนชนะดวง** — ดวงเป็นโจทย์ ฝีมือเป็นคำตอบ (ทอยใหม่, เต๋าบังคับ, จัดกระดาน, อัปหน้าเต๋า)
3. **เห็นทีมโต** — ความแรงที่ได้มาต้องมองเห็นบนจอ (ดาว, เส้นซินเนอร์จี, ชุดเกราะเปลี่ยนตามเลเวล)

## 3. กฎสถาปัตยกรรม (สำคัญที่สุด)

**แยก 3 ชั้น ห้ามข้ามชั้น:**

```
src/
  sim/        ตรรกะเกมล้วน — pure TypeScript
  data/       เนื้อหาเกมเป็นข้อมูล (JSON + schema)
  game/       ชั้นแสดงผล PixiJS: scenes, views, animation, vfx, ui
  platform/   PlatformService: steam / web(dev) — save, achievements, cloud
  app/        bootstrap, settings, i18n, audio
electron/     main process, preload, IPC
tools/        asset pipeline, balance bot
assets/       ไฟล์ภาพที่ประมวลผลแล้ว (สร้างจาก tools เท่านั้น)
raw/          ไฟล์ภาพต้นฉบับจาก ChatGPT + manifest.csv (ห้ามแก้ไข)
tests/
docs/
```

### กฎของ `src/sim/`
- **ห้าม import** PixiJS, DOM, Electron, `window`, `Date.now()`, `Math.random()`
- สุ่มผ่าน **seeded RNG** ตัวเดียวที่ส่งเข้ามา (`rng.next()`) → รันซ้ำด้วย seed เดิมต้องได้ผลเดิม 100%
- รูปแบบ: `state` เป็น plain object ที่ serialize เป็น JSON ได้ทั้งก้อน + `applyAction(state, action, rng) → { state, events[] }`
- sim ส่ง **events** ออกมา (เช่น `DiceRolled`, `TileLanded`, `UnitAttacked`, `UnitDied`, `SynergyActivated`) ชั้น game เอา events ไปเล่นแอนิเมชัน — sim ไม่รู้จักเวลา/เฟรม
- ผลที่ได้: เทสต์ได้, บอทเล่น 1,000 รันในไม่กี่วินาที, save/load ง่าย, replay ได้จาก seed

### กฎของ `src/data/`
- มอน คลื่น ช่อง ยูนิต ซินเนอร์จี เรลิก บอส ตัวเลขบาลานซ์ **อยู่ใน JSON ทั้งหมด** ห้าม hardcode ในโค้ด
- ทุกไฟล์มี schema (zod) และ validate ตอน build — id ซ้ำ/อ้าง id ที่ไม่มี = build fail
- ทุก entity มี `id` แบบ snake_case คงที่ ห้ามเปลี่ยน id หลังปล่อยเกม (save เก่าจะพัง)

### กฎของ `src/game/`
- อ่าน state + เล่น events เท่านั้น **ห้ามแก้ state เอง** ทุกการกระทำของผู้เล่นส่งเป็น action เข้า sim
- ข้อความทุกคำผ่าน `t('key')` ห้ามมี string ภาษาคนในโค้ด (รองรับ EN + TH ตั้งแต่ต้น)

## 4. Asset pipeline (ทำเป็นงานแรก)

โฟลเดอร์ `raw/` มี 5 ชุดจาก ChatGPT พร้อม `manifest.csv` ของแต่ละชุด:
`01_characters`, `02_monsters`, `03_icons`, `04_ui`, `05_effects`

คอลัมน์ manifest: `save_as` (ชื่อไฟล์ใน raw), `background` (alpha / magenta / black / scene / tile),
`slice` (วิธีตัดชีต), `final_size` (ขนาดใช้งาน)

**เขียน `tools/assets/` ให้ทำงานนี้แบบรันซ้ำได้ (`npm run assets`):**
1. **ตรวจสอบก่อน:** เทียบไฟล์ใน `raw/` กับ manifest → พิมพ์รายการที่ขาด/ชื่อไม่ตรง ลง `docs/ASSET_REPORT.md` (ขาดได้ ไม่ต้อง fail — ใช้ placeholder สีพื้นแทน)
2. **พื้นหลัง:** `alpha` ใช้ตามนั้น · `magenta` ทำ chroma key (#FF00FF + ขอบที่เปื้อนชมพู) · `black` **ไม่ลบ** เก็บไว้ใช้ additive blend · ถ้าไฟล์ที่ควรเป็น alpha มาเป็นพื้นทึบ ให้ตรวจจับสีพื้นจากมุมภาพแล้วตัดออก พร้อมรายงาน
3. **ตัดชีต:** รูปจาก AI **ไม่ได้อยู่ตรงกริดเป๊ะ** ห้ามหารความกว้างเท่าๆ กันแล้วตัด — ให้หา bounding box ของแต่ละชิ้นจากพิกเซลที่ไม่โปร่งใส (หรือไม่ดำ สำหรับ effect) แล้วจับคู่ตามลำดับซ้าย→ขวา บน→ล่าง ถ้านับชิ้นได้ไม่ตรงกับ manifest ให้รายงาน ไม่ต้องเดา
4. **จัดวาง:** ตัวละคร/มอนทุกเฟรมของตัวเดียวกันต้อง **เท้าอยู่เส้นเดียวกันและสเกลเดียวกัน** (จัดชิดล่าง กึ่งกลางแนวนอน บนผืนผ้าใบขนาด final_size)
5. **ย่อขนาด:** ลองทั้ง nearest-neighbor และ lanczos+sharpen กับตัวอย่าง 3 ไฟล์ แล้วให้เจ้าของโปรเจกต์เลือกก่อนรันทั้งชุด (ภาพ AI ไม่ใช่ pixel grid จริง nearest อาจแตก)
6. **แพ็ก:** รวมเป็น texture atlas แยกหมวด + ไฟล์ `assets/manifest.json` ที่ map `asset id → frame`
7. ทำหน้า **`/gallery`** (dev เท่านั้น) แสดงทุก asset ที่ตัดแล้วพร้อม id — ให้เจ้าของโปรเจกต์ตรวจด้วยตาก่อนไปต่อ

ถ้าภาพไหนคุณภาพไม่พอ (ตัดไม่ได้, หน้าตาเพี้ยนระหว่างเฟรม, ตัวสะกดบนแบนเนอร์ผิด) → เขียนรายการไว้ใน `docs/ASSET_REPORT.md`
พร้อมบอกว่าต้องสร้างใหม่ด้วยคำสั่งไหน **อย่าแก้ภาพเองเงียบๆ**

### ความสมูท = โค้ด ไม่ใช่เฟรม
แต่ละตัวมีแค่ท่าหลัก (idle / attack / hurt / + victory หรือท่าพิเศษ) แอนิเมชันทำด้วย tween:
- idle: หายใจ (scale Y ±2%, 1.2 วิ วนซ้ำ) · attack: ย่อตัว → พุ่งไปข้างหน้า → สลับเป็นเฟรม attack → เด้งกลับ
- hurt: สลับเฟรม + กระพริบขาว + ถอยหลัง + hit-stop 40–60 ms · ตาย: ยุบตัว + `fx_death_poof`
- เอฟเฟกต์จากพื้นดำเล่นด้วย `blendMode: 'add'` · มี screen shake เบาๆ ตอนคริ/บอสตี · ตัวเลขดาเมจเด้ง
- ทุกค่า timing อยู่ใน `src/game/anim/tuning.ts` ที่เดียว และต้องมีตัวเลือก **ลดการสั่น/แสงกระพริบ** ใน settings

## 5. กติกาเกม V1 (สรุป — รายละเอียดเต็มและตัวเลขอยู่ใน `src/data/`)

**ตาหนึ่ง:** ทอย d6 → เห็นช่องเป้าหมาย → เลือก เดิน / ทอยใหม่ / เต๋าบังคับ → รับผลช่อง → (เลือกอัปช่อง) → ทีมสู้อัตโนมัติ 4 เทิร์น
**ครบรอบ:** ผ่านช่องประตูบอส → สู้บอสจนรู้ผล → เลือกรางวัล 1 ใน 3 (ช่องใหม่ / เรลิก / หน้าเต๋าพิเศษ) → วางช่องบนกระดาน
**แพ้:** หัวใจ 3 ดวง ทีมล้มหรือแพ้บอสเสีย 1 ดวง

- **ลูกเต๋า:** ทอยได้ 6 = คริ x2 ทั้งตา · หน้าเต๋าเปลี่ยนเป็นหน้าพิเศษได้ (★, วาร์ป, ทอง, x2, มงกุฎ)
- **กระดาน:** วงรอบ 16 ช่อง (กริด 5×5 ใช้ขอบนอก) · ช่อง 5 ประเภท: รับยูนิต / บัฟ / เศรษฐกิจ / ฟื้นฟู / ความเสี่ยง · อัปได้ ★1→★3
- **ซินเนอร์จี:** คู่ช่องถึง ★★ ทั้งคู่ = เปิด tier 1, ★★★ ทั้งคู่ = tier 2 · มีเส้นพลังเชื่อมบนกระดาน
- **ยูนิต:** นักดาบ, อัศวิน(แท็งก์), นักธนู(ตีตัวหลัง), จอมเวท(ตีหมู่), นักบวช(ฮีล) · ทีมสูงสุด 6 · เลเวล 3 ขั้น (ภาพเปลี่ยนตาม tier)
- **ผู้นำทีม:** กัปตัน (เริ่มต้น), นักพนัน (ทอยใหม่ฟรี 1/รอบ), พ่อค้า (อัปช่องถูกลง 30%)
- **โชว์คลื่นถัดไป:** แผง NEXT WAVE แสดงมอนที่จะมา → ผู้เล่นวางแผนว่าจะเล็งช่องไหน **(ฟีเจอร์บังคับ — เป็นตัวเชื่อมเต๋ากับการต่อสู้)**
- **มอนออกแบบตามหน้าที่:** ตัวตึง / ฝูง / บิน(ข้ามแท็งก์) / เกราะ / พิษ / ฮีลเลอร์-อัญเชิญ / ระเบิดตอนตาย / ขโมยทอง

## 6. ข้อกำหนดสำหรับ Steam (ออกแบบรองรับตั้งแต่ต้น)

**หน้าจอและอินพุต**
- ออกแบบที่ 1920×1080 สเกลแบบ integer/letterbox รองรับ 1280×720 ถึง 4K, 16:10 (Steam Deck 1280×800) และ ultrawide (มีขอบ)
- Windowed / Borderless / Fullscreen, เลือกความละเอียด, VSync
- **เล่นได้ทั้งเมาส์, คีย์บอร์ด, และ gamepad ครบทุกหน้าจอ** (focus navigation) — จำเป็นสำหรับ Steam Deck
- ตัวอักษรเล็กสุดบนจอ Deck ต้องอ่านออก (เทียบเท่า ≥ 9px ที่ 1280×800) และโชว์ glyph ปุ่มตามอุปกรณ์ที่ใช้

**Save**
- เซฟอัตโนมัติทุกตา → ปิดเกมกลางรันแล้วกลับมาเล่นต่อได้
- 2 ไฟล์: `profile.json` (meta/ปลดล็อก/settings) และ `run.json` (รันปัจจุบัน)
- มี `saveVersion` + ฟังก์ชัน migrate ทีละเวอร์ชัน · เขียนแบบ atomic (เขียน .tmp แล้ว rename) + เก็บ backup 1 ชุด · ไฟล์เสียต้องไม่ทำเกมพัง
- path ผ่าน `app.getPath('userData')` → ตั้ง Steam Auto-Cloud ชี้โฟลเดอร์นี้

**Steam features (ผ่าน `PlatformService` เท่านั้น)**
```ts
interface PlatformService {
  init(): Promise<void>; isSteam: boolean;
  unlockAchievement(id: string): void; setStat(id: string, v: number): void;
  setRichPresence(key: string, v: string): void;
  getLanguage(): string; quit(): void;
}
```
- มี `WebPlatform` (no-op, ใช้ตอน dev/เทสต์) และ `SteamPlatform` · โค้ดเกมห้ามเรียก Steam ตรงๆ
- เกมต้อง**เปิดเล่นได้แม้ Steam ไม่ได้รันอยู่** (fallback เป็น WebPlatform ไม่ crash)
- Achievements 25–30 อัน นิยามใน `data/achievements.json` · sim ส่ง event → ตัวตรวจ achievement แยกต่างหาก
- Steam Overlay ต้องเปิดได้ (Shift+Tab) · Rich Presence บอก Act/รอบ

**คุณภาพขั้นต่ำก่อนส่งรีวิว**
- หน้า Settings: เสียง (Master/BGM/SFX), ภาษา, จอ, ความเร็วเกม x1/x2, ลดการสั่น/แสงกระพริบ, รีเซ็ตเซฟ
- Pause ได้ทุกเมื่อ · หน้า Credits · ปุ่ม Quit · ไม่ค้างเมื่อ alt-tab · เสียงหยุดเมื่อหน้าต่างไม่ focus (ตั้งค่าได้)
- เปิดเกมถึงเมนู < 5 วินาที · 60 FPS บนเครื่องสเปกต่ำ (การ์ดจอออนบอร์ด) · ขนาดติดตั้ง < 500 MB
- global error handler → เขียน log ลงไฟล์ ไม่โชว์จอขาว
- ปิด DevTools, ปิด `nodeIntegration` ใน renderer, ใช้ `contextIsolation` + preload IPC ใน production build
- **Demo build:** flag `DEMO=1` จำกัดแค่ Act 1 + หน้าชวน wishlist ตอนจบ (ใช้ลง Steam Next Fest / หน้า demo)

**เรื่องนอกโค้ดที่เจ้าของโปรเจกต์ต้องทำ (เตือนเมื่อถึง milestone ที่เกี่ยวข้อง)**
- ภาพในเกมสร้างด้วย AI → ต้องประกาศในหัวข้อ Generative AI ของ Steamworks Content Survey (แบบ pre-generated)

## 8. วิธีทำงาน

- เริ่ม session: อ่าน `CLAUDE.md` → `STATUS.md` → `git log -5` → ทำงานต่อจากที่ค้าง
- จบ session หรือจบงานย่อย: อัปเดต `STATUS.md` (ทำอะไรไป / ค้างอะไร / ขั้นต่อไป / การตัดสินใจที่ทำ + เหตุผล)
- commit เล็กและบ่อย ข้อความรูปแบบ `m3: add next-wave panel` · ห้าม commit ถ้า `npm run check` ไม่ผ่าน
- `npm run check` = typecheck + lint + test + validate data
- แก้ bug: เขียนเทสต์ที่ fail ก่อน (ถ้าเป็น bug ใน sim) แล้วค่อยแก้
- ไม่แน่ใจเรื่อง design/ความรู้สึกของเกม → ถาม อย่าเดา · เรื่องเทคนิคล้วน → ตัดสินใจเองแล้วจดเหตุผล
- งานที่ตรวจด้วยตาได้ (แอนิเมชัน, UI) ให้แคปภาพ/บอกวิธีดู และบอกตรงๆ ว่าส่วนไหนยังไม่ได้ทดสอบ
- ห้ามแก้ไฟล์ใน `raw/` · ห้ามแก้ `assets/` ด้วยมือ (สร้างจาก tools เท่านั้น)
- ห้ามใส่ secret (Steam credentials, API key) ลง repo — ใช้ `.env` ที่อยู่ใน `.gitignore`

### มาตรฐานโค้ด
- TypeScript strict, ไม่มี `any` (ยกเว้นมีคอมเมนต์บอกเหตุผล) · ไฟล์ละไม่เกิน ~300 บรรทัด
- ตั้งชื่ออังกฤษ, คอมเมนต์เฉพาะ "ทำไม" · ไม่มี magic number ในโค้ด (ไป `data/` หรือ `tuning.ts`)
- sim: ฟังก์ชัน pure, ไม่ mutate input · game: ห้ามสร้าง object ใหม่ในลูปทุกเฟรม (ใช้ pool กับ particle/ตัวเลขดาเมจ)

## 9. การตัดสินใจที่ยังเปิดอยู่ (ถามเจ้าของโปรเจกต์เมื่อถึงเวลา)

1. **ไลบรารี Steam (ตัดสินที่ M7):** ทดลอง `steamworks.js` กับ `steamworks-ffi-node` ด้วย app id ทดสอบ 480 — เลือกตัวที่ achievements + cloud + **overlay บน Electron** ทำงานจริงกับ Electron เวอร์ชันที่ใช้ และยังมีการดูแลอยู่ แล้วจดผลใน `STATUS.md`
2. **วิธีย่อภาพ** (M1): nearest หรือ lanczos — ให้ดูตัวอย่างแล้วเลือก
3. **แพลตฟอร์มเพิ่ม:** macOS/Linux build และเวอร์ชันมือถือ — หลังวางขาย Windows แล้วค่อยพิจารณา (โครงสร้าง sim/game แยกชั้นไว้รองรับอยู่แล้ว)
4. **ราคา / วันวางขาย / Early Access หรือไม่** — เจ้าของโปรเจกต์ตัดสิน
5. **เสียงและเพลง:** ยังไม่มี asset — ต้องหาแหล่งที่มีสิทธิ์ใช้เชิงพาณิชย์ก่อน M6
