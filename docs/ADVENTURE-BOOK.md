# สมุดผจญภัย (Adventure Book) — เวอร์ชัน 1

> เอกสารออกแบบ ไม่ใช่คู่มือผู้เล่น
> ตัวเลขทุกตัวในไฟล์นี้คำนวณจากข้อมูลจริงในโปรเจกต์ ณ ตอนเขียน
> v1 คือ "รันได้ ครบวง" ไม่ใช่ "สมบูรณ์" — เอาขึ้น VPS ให้คนลองเล่นแล้วค่อยปรับ

## 1. สมุดนี้มีไว้ทำไม

เกมนี้ออกแบบมาให้เล่นอิสระ คนที่เล่นเป็นจะรู้วิธีฟาร์ม วิธีหาของอยู่แล้ว
สมุดผจญภัย **ไม่ได้มาแทนที่การเล่นแบบนั้น** — มันคือ **อีกเส้นทางหนึ่ง**
ที่ให้ของซึ่ง **ไม่มีทางหาได้จากที่อื่นเลย**

หลักการ:
- ต้องยากพอที่คนเก่งจะรู้สึกว่าท้าทาย
- ต้องคุ้มพอที่คนเก่งจะยอมทำ
- ต้องเดินไปเองระหว่างเล่นปกติ ไม่ต้องกดรับเควสต์

## 2. หน่วยพื้นฐานคือ "การ์ด" ไม่ใช่ "แมพ" และไม่ใช่ "ชื่อมอน"

เคยคิดจะทำตามแมพ แต่ข้อมูลจริงบอกว่าไม่เวิร์ค

| มอน | spawn slot ทั่วโลก | เกิดในกี่ภูมิภาค |
|---|---|---|
| PORING | 1,183 | 8 |
| POPORING | 1,176 | 13 |
| GREEN_PLANT | 546 | 10 |
| POISON_SPORE | 452 | 8 |

ถ้ายึดแมพ Poporing จะโผล่ในสมุด 13 ที่ นับแยกกัน

### แล้วก็ไม่ใช่ "ชื่อมอน" ด้วย

ตอนแรกทำเป็นหน้าละ 1 มอน แล้ว log ตอนบูตฟ้องออกมา 11 คู่

```
[WRN] Flail Goblin and Dagger Goblin both drop item 4060...
[WRN] Deniro and Andre both drop item 4043...
[WRN] Fungus and Poison Spore both drop item 4048...
```

ก็อบลิน **5 ตัวดรอป Goblin Card ใบเดียวกัน** — การ์ด 1 ใบเติมได้หน้าเดียว อีก 4 หน้าค้าง ★3 ตลอดกาล
→ ภูมิภาคไม่มีวันจบ → **หมวกรางวัลได้ไม่ได้เลย** (กระทบ Geffen Fields, Morroc Fields, Ant Hell, Orc Dungeon)

**หน้าสมุด = การ์ด 1 ใบ** ไม่ใช่มอน 1 ตัว ก็อบลินทั้ง 5 = หน้าเดียวชื่อ "Goblin"
ฆ่าตัวไหนก็นับหน้าเดียวกัน เป้าหมายรวม spawn ของทั้งกลุ่ม

ไม่ใช่แค่แก้บั๊ก — มันตรงกับที่คนเล่นคิดอยู่แล้ว ไม่มีใครแยก "Flail Goblin" กับ "Axe Goblin" ในหัว

มอนที่ไม่ดรอปการ์ดเลย (8 ตัว) ยังเป็นหน้าของตัวเอง ได้สูงสุด 2 ดาว

**โครงสร้างจริง**

```
การ์ด 1 ใบ (มอน 1 ตัวขึ้นไป)  →  3 ดาว (★1 ล่า / ★2 ล่าเยอะ / ★3 การ์ด)
     ↓ รวมกลุ่ม
ภูมิภาค 1 แห่ง  →  ครบทุกดาว = หมวกประจำภูมิภาค
     ↓ รวมกลุ่ม
ทั้งโลก  →  ครบทุกภูมิภาค = Valkyrie Set + Adventure Rank 10
```

### ชื่อหน้า

- คลุมมอนตัวเดียว → ใช้ชื่อมอน
- คลุมหลายตัว → ใช้ชื่อการ์ดตัด " Card" ออก (`Goblin Card` → `Goblin`) แล้วแสดง "นับรวม: Dagger Goblin, Flail Goblin, ..." ในหน้ารายละเอียด

`!book Flail Goblin` ก็ยังหาเจอ เพราะค้นชื่อสมาชิกด้วย

### ⛔ progress เดิมไม่หาย

`ProgressFlag` ใช้ **id ต่ำสุดในกลุ่ม** ไม่ใช่ id ของการ์ด — หน้าที่คลุมมอนตัวเดียวจึงได้ key เดิมเป๊ะ
ใช้ต่ำสุดไม่ใช่ "ตัวที่ spawn เยอะสุด" เพราะอย่างหลังจะขยับเวลาแก้ spawn แล้ว progress จะดูเหมือนรีเซ็ต

## 3. ข้อมูลมาจากไหน — สมุดสร้างตัวเอง

ไม่เขียนมือสักบรรทัด สร้างตอนเซิร์ฟเวอร์บูตจากไฟล์ที่มีอยู่แล้ว

| ต้องรู้ | อ่านจาก |
|---|---|
| มอนตัวไหนอยู่แมพไหน กี่ตัว | `Script/Spawns/*.txt` → `MapConfig` + `CreateSpawn` |
| แมพไหนอยู่ภูมิภาคไหน | `Db/Instances.csv` |
| มอนตัวไหนดรอปการ์ดอะไร | `Db/DropData.csv` |
| มอนตัวนั้นเลเวลเท่าไหร่ | `Db/Monsters.csv` |

**เพิ่มมอนใหม่ / เพิ่มแมพใหม่ = สมุดขึ้นเอง** ไม่ต้องแตะโค้ด

### มอนอยู่ภูมิภาคไหน

จับไปอยู่ภูมิภาคที่มัน spawn เยอะที่สุด แล้วมี**ตารางกำหนดเองทับ**สำหรับตัวที่เกิดทั่วโลก
(Poporing เกิด 13 ภูมิภาค ระบบอัตโนมัติจับไป Payon Fields ด้วยสัดส่วนแค่ 17% ซึ่งมั่ว)

### มอนที่กรองทิ้ง

- มอนที่มี flag `Boss` / `MVP` — ไม่เข้าสมุด (มี `ServerMilestoneEvent` ดูแลอยู่แล้ว)
- **มอนที่ให้ exp 0** — ต้นไม้ เห็ด หุ่นฝึก (14 ตัว) ไม่ใช่ของที่คนไปล่า
  หุ่นฝึกมี HP แสนหน่วยและเกิดใหม่ทุก 15 วิ ถ้าปล่อยไว้จะเป็นดาวที่ถูกที่สุดในเกม
- มอนที่แมพไม่อยู่ใน `Instances.csv` — **147 ตัว** ส่วนใหญ่คือ ep8-11
  (Abyss Lake, Einbroch, Ayothaya, Gonryun, Hugel, Ice Dungeon, Gefenia, Guild Dungeon)
  → ยกไปเป็นชุดอัปเดตถัดไป แค่เติมแถวใน `Instances.csv` ก็เข้าสมุดเอง

**เหลือเข้าสมุด v1: 256 ตัว ใน 24 ภูมิภาค** (ยืนยันจาก log ตอนบูตจริง)

> ตัวเลขนี้ต่ำกว่าที่ประเมินไว้ตอนออกแบบ (284) เพราะการนับจากไฟล์สคริปต์ตรง ๆ นับเกิน
> 3 ทาง: มันนับทั้งสองฝั่งของ `if(IsFeatureEnabled("DoddlerCustomMonsters"))` ทั้งที่
> flag ปิดอยู่, มันไม่รู้จักคำว่า `MVP` ตัวใหญ่เลยปล่อย MVP หลุดเข้ามา, และมันไปจับ
> `CreateSpawnEvent` ด้วย ตัวเลขจากเซิร์ฟเวอร์คือตัวจริง เพราะมันอ่านจาก spawn rule
> ที่แมพโหลดขึ้นมาจริง

## 4. เป้าหมายไล่ตามความชุก

มอนหายากไม่ควรต้องฆ่าเท่ามอนที่เดินชนทุกก้าว

```
★1 = clamp( spawn slot รวมทั่วโลก ÷ 2 , 50 , 500 )   ปัดขึ้นเป็นหลัก 50
★2 = ★1 × 3
★3 = มีการ์ดของมอนตัวนั้น
```

| มอน | spawn | ★1 | ★2 |
|---|---|---|---|
| Poring | 1,183 | 500 | 1,500 |
| Drops | 643 | 350 | 1,050 |
| Lunatic | 375 | 200 | 600 |
| Thief Bug | 287 | 150 | 450 |
| Raydric | 171 | 100 | 300 |
| Khalitzburg | 56 | 50 | 150 |
| Medusa | 65 | 50 | 150 |

**รวมทั้งสมุด ★1+★2 = 80,400 ตัว**

### ★3 การ์ด — ไม่ต้องเดินไปหาใคร

เดิมออกแบบว่าต้องไปหา NPC แต่พอลงมือทำแล้วไม่จำเป็น: มีจุดเดียวที่ไอเทมทุกชิ้น
ผ่านตอนเข้ากระเป๋า (`Player.AddItemToInventory`) ดักตรงนั้นจุดเดียวก็ครบทุกทาง

**เก็บจากพื้น / เทรด / ซื้อจากตลาด / ถอนจากคลัง — ติ๊กทันทีทุกทาง และไม่กินการ์ด**

การ์ดมีมูลค่าในตลาดกลางที่เราทำไว้แล้ว ถ้ากินทิ้งจะไม่มีใครกล้าทำ

`!book` ยังกวาดกระเป๋าซ้ำให้ทุกครั้งที่เปิดดู เผื่อการ์ดที่มีอยู่ก่อนระบบนี้จะมี

## 7. Adventure Rank

สะสมดาว → Rank 1-10 → บัฟถาวรติดตัว

ค่าที่ได้เป็น**ยอดรวม** ไม่ใช่ส่วนที่เพิ่มจากระดับก่อน

| ระดับ | ดาว | ทุกสเตตัส | Drop | EXP | ตีบวก |
|---|---|---|---|---|---|
| 1 | 30 | +1 | — | — | — |
| 2 | 90 | +2 | — | — | — |
| 3 | 175 | +3 | — | — | — |
| 4 | 280 | +3 | +3% | — | — |
| **5** | 390 | +3 | +6% | — | — |
| 6 | 490 | +3 | +9% | — | — |
| 7 | 580 | +3 | +9% | +3% | +2% |
| 8 | 650 | +3 | +9% | +6% | +4% |
| 9 | 700 | +3 | +9% | +9% | +6% |
| **10** | ครบทุกภูมิภาค | **+5** | **+12%** | **+12%** | **+8%** |

ระดับ 5 ได้ **วาร์ปจากสมุดฟรีทุกแมพ** เพิ่มด้วย (ดูข้อ 8) · ระดับ 10 ได้ **Valkyrie Set** + ฉายา

⛔ **เลขคงที่ ไม่ใช่ % ของทั้งเล่ม** — ถ้าใช้ % วันที่เราเพิ่มภูมิภาคใหม่ คนที่เป็นระดับ 6 มาทั้งเดือน
จะ login มาเจอว่าตัวเองเหลือระดับ 5 ทั้งที่ไม่ได้ทำอะไรผิด เลขคงที่มีแต่จะง่ายลงเมื่อเนื้อหาเพิ่ม
ซึ่งเป็นทิศทางที่ถูกของความผิดพลาด

ตั้งไว้สำหรับสมุดขนาด ~730 ดาว (เนื้อหาปัจจุบัน)

ดาวรวมทั้งสมุด = **751 ดาว** (256 มอน แต่ 17 ตัวไม่ดรอปการ์ด จึงได้ 2 ดาวแทน 3)

### บัฟเกาะกับ UpdateStats ไม่ใช่ status effect

`Player.UpdateStats()` เซ็ตสเตตัสฐานกลับเป็นค่าจริงของตัวละครก่อน แล้วค่อยบวกโบนัสทับ
(`GuildSkills.ApplyTo` ทำแบบนี้อยู่แล้ว) — สมุดเกาะที่เดียวกัน

⛔ **ไม่ใช้แบบ "ได้ระดับแล้วบวก / เสียระดับแล้วลบ"** — คอมเมนต์ในโค้ดเดิมอธิบายไว้แล้วว่าทำไม
พลาดการลบครั้งเดียว (หลุดกิลด์ตอน level up, disconnect กลางคัน) แล้วคนนั้นจะถือพลังนั้นตลอดไป
วิธีนี้ระดับเปลี่ยนก็แค่ "ไม่ถูกบวก" ไม่ต้องย้อนอะไรเลย

**อัตราตีบวกไม่ใช่ stat** เลยไปบวกที่ `EquipmentRefineSystem` ตอนตีจริง

### ระดับถูก cache ไว้ใน `abrank`

นับดาวทั้งเล่ม = เดินทุกหน้า ~250 ครั้ง แต่ `UpdateStats` ถูกเรียกทุกครั้งที่เปลี่ยนของ/เลเวล/ติดบัฟ
นับใหม่ทุกครั้งคือเอาการค้นหลายร้อยครั้งไปแขวนบน path ที่ไม่ควรช้า

นับใหม่เฉพาะตอนที่มันเปลี่ยนได้จริง คือ**ตอนได้ดาว** และตอนเปิด `!book`
เก็บเป็น `ระดับ + 1` เพื่อให้ค่า 0 แปลว่า "ยังไม่เคยนับ" ไม่ใช่ "ระดับ 0"

## 8. วาร์ปจากสมุด

สมุดรู้อยู่แล้วว่ามอนแต่ละตัวยืนอยู่แมพไหนบ้าง แมพละกี่ตัว
(`AdventureBookEntry.Sightings` เรียงจากแมพที่หนาแน่นที่สุดลงมา)
ฝั่ง client ก็มีข้อมูลชุดเดียวกันอยู่แล้วที่ `mon.Spawns` — ไม่ต้อง export อะไรเพิ่ม

เลยเปิดหน้าสมุดมอนตัวไหน ก็เลือกได้เลยว่าจะไปแมพไหน

### สิทธิ์ไม่เท่ากัน — และนั่นคือเจตนา

| ใคร | ทำอะไรได้ |
|---|---|
| ทุกคน ตลอดเวลา | **เห็น**รายชื่อแมพ + จำนวนมอนแต่ละแมพ |
| ได้ ★1 ของมอนตัวนั้นแล้ว | วาร์ปไปแมพนั้นได้ **เสีย Zeny เท่าอัตราคาฟรา** |
| Adventure Rank 5 ขึ้นไป | วาร์ป**ฟรี** ทุกแมพในสมุด |

ได้สามอย่างพร้อมกัน: สมุดให้รางวัลตัวเอง · ตัวละครใหม่ไม่ได้วาร์ปฟรีตั้งแต่วันแรก ·
คาฟรา `Fly_Wing` `Butterfly_Wing` ยังมีเหตุผลจะมีอยู่

### ทำแล้ว: packet ของตัวเอง

```
AdventureBookAction  (client -> server)  Refresh / Warp
AdventureBookData    (server -> client)  Header / Pages / Complete / PageUpdate
```

⛔ **สมุดส่งทีเดียวไม่ได้** — `OutboundMessage` เริ่มที่ 1 KB แล้วคูณสองไปเรื่อย ๆ
พอจะเกิน 10,000 ไบต์มัน **assert** ซึ่งไม่ใช่ packet หายแต่ **เซิร์ฟเวอร์ตายทั้งตัว**
(พารามิเตอร์ `capacity` ใน `StartPacket` ไม่ได้ถูกใช้เลย ขอบัฟเฟอร์ใหญ่กว่านี้ไม่ได้)

เพดานจริง ~8 KB สมุด 247 หน้าพร้อมชื่อและแมพ = เกินหลายเท่า
เลยส่งเป็น `Header` (ภูมิภาค) → `Pages` หลายก้อน (งบก้อนละ 1,800 ไบต์) → `Complete`
**แบ่งตามขนาดที่ประมาณได้ ไม่ใช่ตามจำนวนหน้า** เพราะขนาดหน้าส่วนใหญ่คือความยาวชื่อ ซึ่งต่างกันได้ 3 เท่า

`Warp` ตรวจฝั่งเซิร์ฟเวอร์ครบ **ไม่เชื่อ client สักอย่าง**

1. มีดาว ★ ของมอนตัวนั้นแล้วหรือยัง
2. มอนตัวนั้นอยู่บนแมพที่ขอมาจริงไหม (เทียบกับ `Sightings` ของเซิร์ฟเวอร์เอง)
3. Zeny พอไหม — ค่าเดินทาง `500 + Lv×10` (ต่ำสุด 500 สูงสุด 2000) · **ระดับ 5 ขึ้นไปฟรี**

**หักเงินหลังผ่านครบทุกด่านแล้วเท่านั้น** เที่ยวที่ถูกปฏิเสธจะไม่มีวันเป็นเที่ยวที่จ่ายเงินไปแล้ว

### ⛔ ห้ามใช้ `AdminRequestMove`

ปุ่ม Teleport ในหน้าต่างฐานข้อมูลส่ง `PacketType.AdminRequestMove` ซึ่งเป็นคำสั่ง GM

```csharp
// NetworkManager.cs:1721
msg.Write((byte)PacketType.AdminRequestMove);

// PacketAdminRequestMove.cs:27
if (!connection.IsAdmin && !ServerConfig.DebugConfig.EnableWarpCommandForEveryone)
    return;
```

สมุดต้องมี **packet ของตัวเอง + handler ของตัวเอง** ที่ตรวจสามเงื่อนไขข้างบนฝั่งเซิร์ฟเวอร์
ไม่ใช่ยืม packet admin มาใช้ เพราะ client เชื่อไม่ได้

### ⛔ ต้องปิดก่อนขึ้น VPS

```json
// appsettings.json:44
"EnableWarpCommandForEveryone": true    ← ตอนนี้เปิดอยู่
```

เปิดไว้ = ทุกคนวาร์ปฟรีไม่จำกัดทั่วโลกผ่านหน้าต่างฐานข้อมูล
ซึ่งทำให้ทั้งข้อ 8 นี้ คาฟรา และไอเทมวาร์ป ไม่มีความหมายพร้อมกันทั้งหมด

**เป็นรายการแรกของ checklist ก่อน close beta**

## 9. ฝั่งเทคนิค

### ใครได้เครดิตฆ่า

**ทุกคนที่ตีมอนตัวนั้น** ที่ยังอยู่บนแมพเดียวกันและไม่ตาย — กติกาเดียวกับที่ exp ใช้อยู่
ไม่ใช่คนที่ตีทีสุดท้าย และไม่ใช่คนที่ตีแรงสุดคนเดียว ปาร์ตี้ที่ไปด้วยกันจึงเดินสมุดไปพร้อมกัน
ส่วนคนที่ยืนเฉย ๆ ไม่ได้อะไรเพราะยืนเฉย ๆ ไม่สร้างดาเมจ

⛔ **ห้ามใช้ `RegisterDistributeExperienceEvent` เป็นตัวนับ** — exp จ่ายผ่าน 2 เส้นทาง
และ event ตัวนั้นยิงเฉพาะเส้นทางปาร์ตี้ที่แชร์ exp (`PartyExpAccumulator.cs:143`)
คนเล่นคนเดียวรับ exp ทันทีแล้ว `return` ออกไปเลย (`AddExp` บรรทัด 36-46) จะไม่ถูกนับสักครั้ง
ใช้ `RegisterKillMonsterEvent` แล้วอ่าน `monster.TotalDamageReceived` แทน

### รูปแบบที่เก็บ

หนึ่ง key ต่อหนึ่งมอน ไม่ใช่สอง — จำนวนที่ฆ่าเลื่อนขึ้นไป 3 บิต ดาวที่ได้แล้วอยู่ 3 บิตล่าง

```
ab<monsterId>  ->  (จำนวนที่ฆ่า << 3) | ดาวที่จ่ายไปแล้ว
```

**บันทึกดาวไว้ ไม่ใช่คำนวณจากจำนวน** เพื่อให้การจ่ายรางวัลเกิดครั้งเดียวแน่นอน
ถ้าคำนวณเอา วันไหนเราลดเป้าลง คนที่เลยเส้นใหม่ไปแล้วจะได้รางวัลซ้ำทั้งเซิร์ฟ


### จุดเสียบ

```csharp
// Custom/BountySystem/BountySystemManager.cs เป็นโครงเปล่าที่ register ไว้แล้ว
MonsterRewardManager.RegisterKillMonsterEvent(OnKillMonster);
```

### ที่เก็บ progress

`Player.NpcFlags` — `Dictionary<string, int>` เซฟลง DB พร้อมตัวละครอยู่แล้ว
**ไม่ต้องแก้ schema ไม่ต้อง migration**

```csharp
public int  GetNpcFlag(string flag)            // Player.cs:144
public void SetNpcFlag(string flag, int val)   // Player.cs:149
```

รูปแบบ key: `ab#<monsterId>` (นับ kill) และ `ab*<monsterId>` (bitmask ดาวที่เก็บแล้ว)
ใช้ id ไม่ใช่ชื่อ เพื่อให้ key สั้น — 256 มอน × ~12 ไบต์ ≈ 3.1 KB ต่อตัวละคร ก่อนบีบอัด LZ4

### แจกของ / ประกาศ

```csharp
player.CreateItemInInventory(new ItemReference(item, 1));   // ServerMilestoneEvent.cs:536
ServerAnnouncements.Announce(...)                            // Custom/ServerAnnouncements.cs
```

### ⛔ แก้แล้ว: กับระเบิดตอนเซฟตัวละคร

`PlayerDataDbHelper.StorePlayerDataForDatabaseUse` เคยจองพื้นที่ `NpcFlags.Count * 8`
แต่ `WriteDictionary` ใช้ `ความยาว + UTF8 ของ key + 4` ต่อ entry — key ยาวเกิน 3 ตัวอักษร
ก็เกินโควตาตัวเองแล้ว บัฟเฟอร์เป็น `MemoryStream` คร่อม array ที่ขยายไม่ได้
เขียนเกิน = โยน exception ออกจากการเซฟตัวละคร

แทนที่ด้วย `NpcFlagStorageSize()` ที่วัดจริง — **ต้องมีก่อนสมุดจะเพิ่ม key เป็นร้อย**
