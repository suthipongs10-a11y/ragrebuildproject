# แผนการสร้าง — Muay Manager

สรุปว่าจะสร้างเกมนี้อย่างไร และลำดับงานของ M0
ภาพรวมทั้ง 6 milestone อยู่ใน blueprint ข้อ 11 เอกสารนี้ลงรายละเอียดเฉพาะส่วนที่จะทำก่อน

---

## 1. สรุปแนวทาง

```
นักมวย 2 ฝั่ง + แผนรายยก + ค่าสุ่มตั้งต้น
        ↓
packages/sim      เดินทีละ 1/60 วินาทีแบบคงที่ ไม่มีโค้ดภาพ
        ↓
รายการเหตุการณ์ต่อยก (JSON)
        ↓
packages/presenter   เล่นท่า กล้อง เอฟเฟกต์ เสียง ตามเหตุการณ์
```

เหตุผลที่ทุกอย่างพึ่งการแยกนี้
- ภาพเปลี่ยนจาก 2D เป็น 3D ได้โดยไม่แตะกติกา
- กล้องและท่ารับรู้ผลล่วงหน้า จึงจัดท่าเข้าคู่และสโลว์หมัดน็อกได้
- เซิร์ฟเวอร์รันโค้ดชุดเดียวกัน กันโกงและไม่ต้องออนไลน์พร้อมกัน
- ทุกไฟต์เป็นรีเพลย์ขนาดเล็กที่แชร์ได้
- ปรับสมดุลด้วยการจำลองหลายพันไฟต์ในไม่กี่วินาที

**ลำดับการลงทุน:** พิสูจน์ว่าไฟต์สนุกและแผนมีผลด้วย 2D ก่อน (M0) แล้วค่อยลงทุน 3D (M1) ซึ่งเป็นส่วนที่แพงและเสี่ยงที่สุด ถ้า 3D ไม่ผ่าน ตัวจำลองทั้งหมดยังใช้ต่อกับ 2D ได้

## 2. เครื่องมือ

| ส่วน | เครื่องมือ | หมายเหตุ |
|---|---|---|
| ภาษา | TypeScript | ทั้งโปรเจกต์ |
| โครง | npm workspaces | ไม่เพิ่มเครื่องมือจัด monorepo จนกว่าจะจำเป็น |
| ตัวจำลอง | TypeScript ล้วน ไม่มี dependency | รันได้ทั้งเบราว์เซอร์และ Node |
| ทดสอบ | Vitest | ชุดทดสอบผลเดิมทุกครั้ง |
| ตัวเล่นภาพ M0 | Canvas 2D | ยกโครงกระดูกและท่าจากเดโม |
| หน้าจอ M0 | Vite + TypeScript + HTML | ยังไม่ใช้ framework จนกว่าจะถึง M2 |
| จำลองจำนวนมาก | สคริปต์ Node ใน `tools/balance` | ออกรายงานเป็นตารางและ JSON |
| 3D (M1) | three.js + GLB | รอยืนยัน |
| มือถือ (M2+) | Capacitor | รอยืนยัน |
| เซิร์ฟเวอร์ (M3) | Node.js | รัน `packages/sim` ชุดเดียวกัน |

ตัวสุ่ม: mulberry32 หรือเทียบเท่า รับค่าตั้งต้น 32 บิต แยกสายสุ่มต่อยก (`seed` ของไฟต์ + เลขยก) เพื่อให้แก้แผนระหว่างยกแล้วเล่นซ้ำได้
เลขทศนิยม: ใช้จังหวะคงที่และหลีกเลี่ยงฟังก์ชันที่ผลต่างกันตามเครื่อง ชุดทดสอบ M3 จะยืนยันว่าเซิร์ฟเวอร์กับแอพได้ผลตรงกัน

## 3. ลำดับงาน M0

แต่ละขั้นจบด้วยของที่รันได้และตรวจได้ ทำทีละขั้น

### M0.1 ย้ายกติกาเดโมเป็นตัวจำลอง
- ตั้ง workspace, `packages/sim`, `packages/data`
- ย้ายค่าจากเดโมเป็นไฟล์ข้อมูล: 8 ท่า 3 ท่าไม้ตาย 4 สาย สูตรใน blueprint ข้อ 3.6
- เขียนตัวจำลองใหม่ให้ไม่มีโค้ดภาพ ใช้ตัวสุ่มมีค่าตั้งต้น
- **ข้อควรระวัง:** เดโมใช้ตำแหน่งข้อต่อจากท่าทาง (`o.j.hd`) หาจุดกระทบ ตัวจำลองใหม่ต้องใช้ระยะและเป้าเท่านั้น จุดกระทบบนจอเป็นหน้าที่ของตัวเล่นภาพ
- ตรวจ: ชุดทดสอบยืนยันว่าค่าตั้งต้นเดิมให้รายการเหตุการณ์เดิมทุกไบต์

### M0.2 สคริปต์จำลองจำนวนมาก
- `tools/balance`: รัน N ไฟต์ รายงานการกระจายผลตาม `CLAUDE.md` ข้อ 4 และตัววัดความสนุกใน `FIGHT_DESIGN.md` ข้อ 11
- ตรวจ: ผลของกติกาเดิมต้องใกล้กับที่เดโมรายงาน (น็อกเกือบทั้งหมด จบยก 2 เป็นส่วนใหญ่) เพื่อยืนยันว่าย้ายถูก ก่อนเริ่มแก้อะไร

### M0.3 ตัวเล่นภาพ 2D จากรายการเหตุการณ์
- ยกโครงกระดูก ท่า เวที เอฟเฟกต์ และเสียงจากเดโมมาไว้ใน `packages/presenter`
- เล่นจากรายการเหตุการณ์อย่างเดียว เพิ่มท่าเข้าคู่ (ผู้รับเริ่มท่ารับก่อนกระทบ)
- `apps/client`: หน้าเดียว ดูไฟต์ ชกใหม่ สุ่มคู่ เร็ว ×2 เสียง เล่นซ้ำจากค่าตั้งต้น
- ตรวจ: **เจ้าของเกมเปิดดูแล้วยืนยันว่าไม่แย่กว่าเดโม** ← จุดหยุดรอคำยืนยันจุดแรก

### M0.4 ระบบที่ทำให้ไฟต์มีเรื่องเล่า
ทำทีละระบบ จำลอง 2,000 ไฟต์หลังแต่ละระบบ
1. ช่วงของไฟต์: ดูเชิง แลก หายใจ โค้งสุดท้าย
2. อาการเมาหมัดและช่วงไล่ถล่ม
3. ค่าคาง
4. ผลสะสมตามเป้า 3 จุด พร้อมร่องรอยบนตัว
5. คอมโบที่ตั้งชื่อได้
6. การกอดปล้ำ
7. ติดเชือกและติดมุม

### M0.5 แผนการชก
- ตัวเลือกตาม blueprint ข้อ 3.4: ท่าที ระยะ เป้าเน้น การใช้แรง ท่าไม้ตาย 3 ช่อง
- จำลองทีละยก หน้าจัดแผนก่อนชกและช่วงพักยกพร้อมเวลาจำกัด
- คำแนะนำพี่เลี้ยงจากสถิติจริงของยกที่ผ่านมา
- ฝั่งตรงข้ามใช้แผนรายยกที่ตั้งไว้ล่วงหน้า
- ตรวจ: สคริปต์วัดว่าแผนที่แก้ทางถูกเพิ่มอัตราชนะอย่างน้อย 10 จุดเมื่อค่าพลังเท่ากัน

### M0.6 ท่าเพิ่ม
- ท่าพื้นฐานที่ 9–16 และแม่ไม้ครบ 12 ท่า พร้อมท่าทางบนโครงกระดูก 2D
- การนำเสนอท่าไม้ตาย: มุมกล้องเฉพาะ ชื่อสองภาษา เล่นซ้ำหมัดน็อก
- สรุปหลังไฟต์

### M0.7 ปรับสมดุลและรายงาน
- ปรับค่าใน `packages/data` จนผ่านเป้าทุกข้อ
- รายงาน: ตารางผลเทียบเป้า ตัววัดความสนุก สิ่งที่ยังไม่ผ่านและเหตุผล
- **หยุดรอเจ้าของเกม** ← จุดจบของ M0

## 4. เกณฑ์ผ่าน M0

1. ผลกระจายตามเป้าใน `CLAUDE.md` ข้อ 4 จากการจำลองอย่างน้อย 2,000 ไฟต์
2. แผนที่แก้ทางคู่ชกได้ถูกเพิ่มอัตราชนะอย่างน้อย 10 จุดเมื่อค่าพลังเท่ากัน
3. ข้อมูลเข้าเดิมให้รายการเหตุการณ์เดิมทุกครั้ง
4. เจ้าของเกมดูไฟต์ 2D แล้วยืนยันว่าสนุกกว่าเดโม
