# ทำเกมเป็นแอป iOS / Android: โฆษณาและการซื้อ — Muay Manager

เขียน 17 พ.ย. 2026 ที่ต้นแบบ 2.50 ฝั่งเกมพร้อมแล้ว (โค้ดใน `prototypes/fight3d/src/mon.js` และ `game.js`) ฝั่งแอปยังไม่ได้ทำ
เอกสารนี้บอกว่าตัวห่อแอปต้องให้อะไรกับเกม และต้องตั้งค่าอะไร

## 1. เกมทำอะไรได้แล้ว

| ส่วน | พฤติกรรม |
|---|---|
| โบนัสจากโฆษณา (เลือกดูเอง) | หลังชนะ: เงินรางวัลไฟต์นั้นอีกเท่าตัว (วันละ 3) • ที่ค่ายเมื่อล้าตั้งแต่ 30%: นวดคลายล้า −25 (วันละ 2) • หลังแพ้: ล้างความล้าของไฟต์นั้นและได้สิทธิ์ล้างตาวันนี้ (วันละ 1) • เพดานนับตามวันจริง |
| โฆษณาคั่น | ตอนกดกลับค่ายหลังไฟต์ของตัวเอง ทุกไฟต์ที่ 3 • ไม่มีรอบไฟต์ท้าชกระหว่างผู้เล่น ไม่มีก่อนหรือระหว่างชก |
| แพ็กเจ้าของค่าย (ซื้อครั้งเดียว รหัสสินค้า `camp_owner`) | ไม่มีโฆษณาคั่น • รับโบนัสข้างบนได้ทันทีไม่ต้องดู (เพดานเท่าเดิม) • ได้สีครบ 9 สี • ดาวทองหน้าชื่อในตารางอันดับ |
| กู้คืนการซื้อ | ปุ่มในการ์ดแพ็กและในหน้าตั้งค่า • ตอนเปิดแอป เกมถามสโตร์เองว่าเป็นเจ้าของแพ็กหรือไม่ และเชื่อสโตร์ |

สามโหมด (`MON.mode()`): `native` เมื่อมี `window.MuayNative` • `test` เมื่อเปิดหน้าด้วย `?mon=test` (โฆษณาและการซื้อจำลอง ไม่ตัดเงิน ใช้ลองบนเว็บ) • `none` หน้าเว็บปกติ (ไม่แสดงปุ่มโฆษณา การ์ดแพ็กขึ้นว่าเร็ว ๆ นี้ และนับคนกดลง `/api/log`)

ลองได้เลย: `https://muay-manager.pages.dev/?mon=test`

## 2. สิ่งที่ตัวห่อแอปต้องให้: `window.MuayNative`

ต้องมีก่อนสคริปต์ของเกมเริ่มทำงาน ทุกฟังก์ชันคืน Promise เกมไม่เรียกไลบรารีโฆษณาหรือการซื้อเอง

```js
window.MUAY_API = 'https://muay-manager.pages.dev/api';   // ที่อยู่เซิร์ฟเวอร์เกม (หน้าในแอปเป็นไฟล์ในเครื่อง)
window.MUAY_WEB = 'https://muay-manager.pages.dev';       // ใช้ทำลิงก์ชวนเพื่อนมาดู
window.MuayNative = {
  rewarded(placement),   // 'purse' | 'massage' | 'revenge' → {rewarded: true} เมื่อดูจนจบ, {rewarded: false} เมื่อปิดก่อนหรือไม่มีโฆษณา
  interstitial(),        // แสดงโฆษณาคั่นถ้ามีพร้อม แล้ว resolve (ไม่มีก็ resolve เลย)
  products(),            // → {camp_owner: {price: '฿99.00'}}  ราคาเป็นข้อความตามสโตร์ของผู้ใช้
  purchase(productId),   // → {ok: true} เมื่อสโตร์ยืนยันว่าซื้อสำเร็จ
  owned()                // → ['camp_owner'] รายการที่บัญชีสโตร์นี้เป็นเจ้าของ (ใช้กู้คืนการซื้อ)
};
```

เซิร์ฟเวอร์เกมรับคำขอข้ามที่มาแล้ว (`Access-Control-Allow-Origin: *` ผู้เล่นยืนยันตัวด้วยกุญแจใน header ไม่ใช้คุกกี้)

## 3. ขั้นตอนฝั่งแอป (ยังไม่ได้ทำ ต้องใช้เครื่องที่มี Android Studio และ Xcode)

1. โครงแอป (ข้อเสนอ: Capacitor): ใส่ไฟล์จาก `prototypes/fight3d/dist/site/` ทั้งโฟลเดอร์ลงในแอป (เกมต้องอยู่ในแอป ไม่โหลดหน้าเว็บจากเน็ต Apple ไม่รับแอปที่เป็นแค่หน้าเว็บห่อ)
2. ไฟล์เชื่อม (โหลดก่อนเกม): ตั้ง `MUAY_API` `MUAY_WEB` และสร้าง `MuayNative` จากไลบรารีโฆษณา (AdMob) และไลบรารีการซื้อที่เจ้าของเกมใช้อยู่
3. AdMob: รหัสแอปของ iOS และ Android • หน่วยโฆษณาแบบให้รางวัล 1 หน่วย (ใช้ร่วมทั้งสามจุด หรือแยกสามหน่วยเพื่อดูสถิติรายจุด) • หน่วยโฆษณาคั่น 1 หน่วย • ระหว่างพัฒนาใช้รหัสทดสอบของ Google เท่านั้น
4. สินค้าในสโตร์: `camp_owner` แบบซื้อครั้งเดียวไม่หมดอายุ (non-consumable) ทั้งสองสโตร์ ตั้งราคาเป็นบาท
5. ตรวจตามกติกา: บอกชัดก่อนดูว่าได้อะไร (ปุ่มของเกมเขียนไว้แล้ว) • ผู้เล่นกดเองทุกครั้ง • มีปุ่มกู้คืนการซื้อ (มีแล้ว) • หน้านโยบายความเป็นส่วนตัวและการลบบัญชี (ยังไม่มี: งานเซิร์ฟเวอร์ P3/P4)

## 4. ที่ต้องได้จากเจ้าของเกม

- ระบบเติมเงินที่ "พร้อมแล้ว" คือไลบรารีหรือบริการอะไร (เช่น RevenueCat ปลั๊กอินของสโตร์โดยตรง หรือระบบของโปรเจกต์อื่น) และมีโครงแอปอยู่แล้วหรือยัง
- รหัสแอปและรหัสหน่วยโฆษณาของ AdMob (ไม่ใช่ความลับ ใส่ในโค้ดแอปได้)
- ชื่อแอปจริง รหัสแพ็กเกจ (เช่น `com.xxx.muaymanager`) และราคาของแพ็ก
- ใครเป็นคนสร้างไฟล์แอป: เซสชันบนคลาวด์สร้างไฟล์ iOS ไม่ได้ (ต้องใช้ Mac) และไม่มีกุญแจเซ็นแอป

## 5. ข้อจำกัดที่รู้

- ของที่ได้จากโฆษณาและสถานะเจ้าของแพ็กเก็บในเซฟของผู้เล่น ยังไม่ได้ให้เซิร์ฟเวอร์ตรวจ (งานเซิร์ฟเวอร์ P2) คนที่แก้เซฟเองได้ก็ปลอมได้ ในแอป สถานะแพ็กจะถูกแก้กลับตามที่สโตร์ตอบทุกครั้งที่เปิด
- "ซ้อมเพิ่ม" ยังไม่ได้ทำเป็นของจากโฆษณา เพราะตอนนี้กดนอนข้ามวันได้ไม่จำกัด ต้องตัดสินเรื่องความเร็วของวันก่อน
- ยังไม่ได้ทดสอบกับ AdMob และสโตร์จริง ทดสอบได้แค่โหมดจำลอง (`npm run e2e:mon`)
