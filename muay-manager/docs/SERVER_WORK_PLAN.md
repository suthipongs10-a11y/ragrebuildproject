# แผนงานเซิร์ฟเวอร์: ให้เซิร์ฟเวอร์เป็นผู้ตัดสิน — Muay Manager

เขียน 16 พ.ย. 2026 ที่ต้นแบบ 2.46 (ตัวจำลอง proto-0.20) สำหรับผู้รับช่วงงานต่อ (Claude ในเซสชันใหม่)
เอกสารนี้ขยายข้อ 8 ของ `docs/ONLINE_STORE_PLAN.md` ให้เป็นงานที่ทำตามได้ทีละขั้น

## 0. วิธีใช้เอกสารนี้

1. อ่าน `muay-manager/CLAUDE.md` (กติกา) → เอกสารนี้ → `STATUS.md` ส่วนรอบ 65–67 → `docs/ONLINE_STORE_PLAN.md` ข้อ 8 แค่นี้พอ ไม่ต้องอ่านทั้ง repo
2. ทำ **ทีละเฟส** ตามลำดับ P0 → P1 → P2 … ห้ามข้าม แต่ละเฟสจบด้วย: ทดสอบผ่าน → ขึ้นเว็บ → อัปเดต `STATUS.md` → commit/push → บอกเจ้าของเกมว่าต้องลองอะไร
3. จุดที่เขียนว่า **ถามเจ้าของเกมก่อน** ให้หยุดถามจริง อย่าเดา (ข้อ 3) ที่เหลือใช้ค่าแนะนำแล้วทำต่อได้
4. เจ้าของเกมประหยัดค่าใช้จ่าย: ใช้ grep/อ่านเฉพาะส่วน อย่าอ่านไฟล์ใหญ่ทั้งไฟล์ (`game.js` 1,400 บรรทัด บรรทัดยาวมาก ให้ `grep -n` หาฟังก์ชันแล้ว `sed -n 'a,bp' | cut -c1-400`)
5. ตอบเจ้าของเกมเป็นภาษาไทย สั้น บอกตรง ๆ ว่าอะไรทดสอบแล้ว อะไรยังไม่ได้ทดสอบ

## 1. สภาพปัจจุบัน

ทุกอย่างอยู่ใน `muay-manager/prototypes/fight3d/`

| ส่วน | ไฟล์ | หน้าที่ |
|---|---|---|
| ตัวจำลอง | `src/sim.js` `src/data.js` | JavaScript ล้วน ไม่มี DOM ไม่มี `Math.random`/`Date.now` ข้อมูลเข้าเดิมได้ผลเดิม `simulate({seed, specs, plans, rules})` → `{events, ticks, result}` |
| ภาพ | `src/main.js` `src/timeline.js` และอื่น ๆ | เล่นภาพจากเหตุการณ์ ไม่ตัดสินผล ไฟต์สดเดินตามนาฬิกา (`followClock`) |
| เกม | `src/game.js` | หน้าจอ เซฟ กติกาเกม (ซ้อม ซื้อ ชก) **ปนกับ UI ในไฟล์เดียว** ส่วนท้าชกอยู่ราวบรรทัด 840–1195 |
| ที่เก็บข้อมูลฝั่งเบราว์เซอร์ | `src/netdb.js` | เลียน API ของ artifact db เรียก `/api` ถามซ้ำทุก 8 วินาที วัดส่วนต่างนาฬิกาเซิร์ฟเวอร์ (`skew`) |
| เซิร์ฟเวอร์ | `functions/api/[[route]].js` (81 บรรทัด) | Cloudflare Pages Functions + D1: สมัคร (`players`) เก็บเอกสาร (`docs`) เก็บ error (`logs`) **ไม่มีกติกาเกมเลย** |
| ไฟล์เกม | `functions/[[path]].js` | ส่งไฟล์จาก KV (`SITE`) |

ข้อมูลที่เก็บตอนนี้ (ตาราง `docs`): `board/<id>` (ชื่อ RP สถิติ ค่าพลัง `seen` `in`) • `challenges/<ผู้ท้า>` และ `answers/<ผู้รับ>` (คำท้า คำตอบ แผน heartbeat) • `data/users/<id>/save` (เซฟทั้งก้อน)
ผู้เล่นเขียนได้เฉพาะเอกสารของตัวเอง แต่ **เขียนอะไรลงไปก็ได้** จุดที่โกงได้ดูตารางใน `docs/ONLINE_STORE_PLAN.md` ข้อ 8

ตัวเลขที่วัดแล้ว: จำลอง 1 ไฟต์ราว 9 มิลลิวินาทีบน Node (508 เหตุการณ์ วัด 16 พ.ย. 2026) • Cloudflare Workers แผนฟรีให้ CPU 10 มิลลิวินาทีต่อคำขอ
**วัดบนเว็บจริง 17 พ.ย. 2026 (แผนฟรี):** เรียกให้เซิร์ฟเวอร์จำลองไฟต์ 60 ครั้งต่อเนื่อง และ 48 ครั้งแบบพร้อมกันทีละ 8 ได้ผล 200 ครบ 108 ครั้ง ไม่มีข้อผิดพลาด CPU เกิน (1102) ผลตรงกับ Node • อ่านเวลา CPU จริงจาก Cloudflare ไม่ได้ (token ไม่มีสิทธิ์ดูสถิติ) จึงรู้แค่ว่า "ผ่าน" ไม่รู้ว่าเหลือเผื่อเท่าไร → **เริ่ม P1 บนแผนฟรีได้** โดยให้แต่ละคำขอจำลองไม่เกิน 1 ไฟต์ และให้ฝั่งเกมส่ง error ลง `/api/log` เมื่อคำขอล้มเหลว จะได้รู้ถ้าเริ่มชนเพดาน (ดูข้อ 3 ก.)

## 2. สิ่งที่ต้องรู้ก่อนแตะโค้ด (บทเรียนที่เจ็บมาแล้ว)

การขึ้นเว็บ
- คำสั่ง (token จริงถูกใส่โดย proxy ของ environment ใช้ค่าหลอกได้ ห้ามขอ token ในแชต):
  ```bash
  cd muay-manager/prototypes/fight3d
  export CLOUDFLARE_API_TOKEN=proxy-injected-dummy-token-0000000000000
  export CLOUDFLARE_ACCOUNT_ID=<ถามจาก API: curl -s -H "Authorization: Bearer x" https://api.cloudflare.com/client/v4/accounts>
  npm run build && node tools/deploy-site.mjs --no-build
  ```
  แล้วตรวจว่า `curl https://muay-manager.pages.dev/version.json` ตรงกับ `dist/site/version.json`
- **ทุกครั้งที่ขึ้นเว็บต้องเพิ่ม `VER` และ `BUILD` ใน `game.js`** (บรรทัด `const VER = '2.46', BUILD = 246;`) เกมที่เปิดค้างอ่าน `version.json` ทุก 2 นาทีแล้วโหลดหน้าใหม่เอง ถ้าไม่เพิ่ม ผู้เล่นจะค้างรุ่นเก่า และสองเครื่องคนละรุ่นจะเห็นไฟต์ไม่ตรงกัน (เคยเกิดแล้ว รอบ 65)
- Cloudflare ตัด header `ETag` ของหน้าแรกทิ้ง อย่าใช้ ETag ตรวจรุ่น • KV ใช้เวลาแพร่ได้ถึงราว 1 นาที
- หน้า claude.ai (artifact) จำกัด 16 MiB ตอนนี้เหลือ 41 KB `build.mjs` จะ throw ถ้าเหลือต่ำกว่า 20 KB ทางแก้: ลด `VOICE_LITE` ใน `build.mjs` (เสียงพากย์บนหน้า artifact จะน้อยลง) หน้า artifact ไม่มี `/api` (ดู `CLOUD.site`)
- หลังขึ้นเว็บ ให้ publish หน้า artifact ด้วย (เครื่องมือ Artifact, `file_path` = `dist/muay-manager.html`, `url` = `https://claude.ai/artifact/L5xitA9BSkMUSPzDiKmp2n`)

โค้ด
- ปุ่มใน `#gMatch` (ป้ายด้านบน) รับการกดผ่าน `$('gMatch').addEventListener('click', onClick)` ถ้าเพิ่มกล่องใหม่นอก `#game`/`#gBody` ต้องผูกตัวรับการกดเอง (เคยลืม ปุ่มกดไม่ติดทั้งรุ่น)
- `bannersHtml()` ต้องไม่มีข้อความที่เปลี่ยนตามเวลา ตัวนับถอยหลังใช้ `data-cd="<เวลา ms>"` แล้ว `fillCountdowns()` เติมให้
- เวลาของไฟต์สดใช้ `now()` (= นาฬิกาเครื่อง + `CH.skew`) ห้ามใช้ `Date.now()` ตรง ๆ กับเวลานัด
- เขียนเอกสารของตัวเองผ่าน `myDoc()` เท่านั้น (คิวเดียว กันเขียนทับกัน)
- แก้ `sim.js` หรือ `data.js` (ค่าสมดุล) เมื่อไร ต้อง `npm test` และ `npm run batch` 2,000 ไฟต์ เทียบเป้าใน `CLAUDE.md` ข้อ 4 แล้วเพิ่ม `SIM_VERSION`

การทดสอบ
- `npm test` ผลซ้ำได้ 200 seed • `node tools/commentary-check.mjs` ตัวตรวจคำพากย์
- ทดสอบทั้งเกมด้วยเบราว์เซอร์จริง (ต้อง `npm run build` ก่อน):
  - `npm run e2e:single` ไฟต์ปกติ: เวที พักยก แก้แผน ชกต่อ ได้ผล (ไม่ต้องมีเซิร์ฟเวอร์)
  - เปิดเว็บจำลอง: `rm -rf .wrangler/state/v3/d1; npx wrangler pages dev dist/site --port 8788 --ip 127.0.0.1` แล้ว
  - `npm run e2e:challenge` ออนไลน์/ออฟไลน์ นัด ถอนตัว ท้าเดี๋ยวนี้ นับถอยหลัง เข้าเวที ผู้ชมจากลิงก์ (3 เบราว์เซอร์ ราว 3 นาที)
  - `npm run e2e:live` ชกสดครบไฟต์สองจอ เทียบเวที แต้ม แผนพักยก ผล (ราว 5–7 นาที)
  - `npm run e2e:update` เกมที่เปิดค้างโหลดรุ่นใหม่เอง
- เครื่องทดสอบวาดได้ราว 2 เฟรมต่อวินาที **ให้รอด้วยสถานะ (`waitForFunction`) อย่ารอด้วยเวลา** • ต้องล้าง `.wrangler/state/v3/d1` ก่อนรัน (รายชื่อท้าชกแสดงแค่ 12 คน)
- ทดสอบบนเว็บจริงได้: `SITE=https://muay-manager.pages.dev/ CLEAN=1 NAMES="ทดสอบระบบ1,ทดสอบระบบ2" npm run e2e:challenge` สคริปต์ลบผู้เล่นทดสอบเองตอนจบ **ตรวจซ้ำทุกครั้ง** ว่าไม่ค้าง (`npx wrangler d1 execute muay-manager --remote --command "SELECT id, json_extract(data,'$.name') FROM docs WHERE coll='board'"`) และ **ห้ามแตะแถวของผู้เล่นจริง**

โครงที่ย้ายได้ (เพราะที่รันอาจเปลี่ยนเป็น VPS): แยกเป็นสามชั้น

- `functions/api/match.js` ตัวต่อของ Cloudflare: แปลงคำขอเป็นการเรียก core และ `store` ที่เขียนลง D1
- (เมื่อย้ายจริง) `server/node.mjs` ตัวต่อของ VPS: เซิร์ฟเวอร์ Node + SQLite ที่ให้เส้นทาง `/api` ชุดเดียวกันและส่งไฟล์ `dist/site` พร้อม `deploy/` (systemd nginx สคริปต์ดึงโค้ดจาก GitHub) ยังไม่ต้องทำจนกว่าเจ้าของเกมยืนยัน

ตารางใหม่ใน D1 (เพิ่มใน `schema()`):
```sql
CREATE TABLE IF NOT EXISTS matches (
  id TEXT PRIMARY KEY,           -- 'm_' + 16 hex
  a TEXT NOT NULL, b TEXT NOT NULL,          -- ผู้ท้า ผู้ถูกท้า (id ผู้เล่น)
  state TEXT NOT NULL,           -- sent | on | off | declined | done
  quick INTEGER NOT NULL, time INTEGER NOT NULL, until INTEGER,   -- ท้าเดี๋ยวนี้ / เวลานัด / หมดเวลาตอบ
  start INTEGER, seed INTEGER, sim TEXT,     -- ระฆัง เมล็ดสุ่ม (สุ่มตอนรับคำท้า) รุ่นตัวจำลอง
  venue TEXT NOT NULL,
  a_side TEXT NOT NULL, b_side TEXT,         -- JSON {name, spec, look, body, plans: [ยก1, ยก2?, ยก3?], build}
  result TEXT, reward TEXT,                  -- JSON เมื่อจบ
  created INTEGER NOT NULL, updated INTEGER NOT NULL);
CREATE INDEX IF NOT EXISTS matches_a ON matches (a, updated);
CREATE INDEX IF NOT EXISTS matches_b ON matches (b, updated);
CREATE INDEX IF NOT EXISTS matches_live ON matches (state, start);
```

เส้นทางใหม่ (แยกไฟล์ `functions/api/match.js` แล้วเรียกจาก `[[route]].js` ทุกเส้นทางที่เขียนต้องมี Bearer ของผู้เล่น):

| เส้นทาง | ใครเรียก | กติกาที่เซิร์ฟเวอร์ตรวจ |
|---|---|---|
| `POST /api/match` `{to, quick, time, venue, side}` | ผู้ท้า | `to` มีจริงและไม่ใช่ตัวเอง • ไม่มีแมตช์ค้างกับคู่นี้ • `time` อยู่ในช่วง ตอนนี้ ถึง +48 ชม. (ท้าเดี๋ยวนี้: `until = now + QUICK_WAIT`) • กรอง `side` ด้วย `cleanSpec`/`cleanPlan` • เวทีอยู่ในรายการ |
| `POST /api/match/<id>/answer` `{accept, side}` | ผู้ถูกท้า | state `sent` • ท้าเดี๋ยวนี้ต้องไม่เกิน `until` • รับ: `start = max(time, now + READY)` **สุ่ม `seed` ด้วย `crypto.getRandomValues` ตอนนี้** state `on` |
| `POST /api/match/<id>/withdraw` | ฝ่ายใดก็ได้ | state `sent` (ผู้ท้ายกเลิก) หรือ `on` และ `now < start − QUIT_UNTIL − 500` → `off` |
| `POST /api/match/<id>/plan` `{round, plan}` | คู่ชก | state `on` • จำลองด้วยแผนที่รู้แล้วเพื่อหาเวลาพักยก (`restWalls`) • รับเฉพาะช่วงตั้งแต่เริ่มพักยกก่อนยกนั้น ถึง +`LIVE_PICK` +1 วินาที |
| `GET /api/match/<id>` | ใครก็ได้ | ส่งตามกติกาการมองเห็นข้างล่าง • ถ้าถึงเวลาแล้วยังไม่ได้สรุปผล ให้สรุปก่อนตอบ |
| `GET /api/match?mine=1` / `?live=1` | เจ้าของ / ใครก็ได้ | แมตช์ของฉัน 3 วันล่าสุด / แมตช์ที่ `on` ซึ่งระฆังอยู่ในช่วง −5 ถึง +15 นาที และที่เพิ่งจบ |

กติกาการมองเห็น (หัวใจของการกันโกง เขียนเป็นฟังก์ชันเดียว `view(row, who, now)` แล้วเขียนทดสอบให้ครบทุกแถว):
- เปิดเสมอ: ชื่อ ชุด ตัวนักมวย ค่าพลัง เวที สถานะ เวลา
- `seed`: ส่งเมื่อ `now ≥ start − QUIT_UNTIL` เท่านั้น (ช่วงที่ถอนตัวไม่ได้แล้ว ไม่งั้นคำนวณผลแล้วหนีได้)
- แผนยก 1 ของอีกฝ่าย: ส่งพร้อม `seed` • แผนยก 2 และ 3 ของอีกฝ่าย: ส่งเมื่อถึงเวลา `LIVE_READ` ของพักยกนั้น (หลังปิดรับแผนแล้ว) • แผนของตัวเองเห็นเสมอ
- `result`: ส่งเมื่อเวลาของไฟต์บนนาฬิกาเซิร์ฟเวอร์จบแล้ว

การสรุปผล: Pages Functions ไม่มีงานตั้งเวลา ให้สรุปตอนมีคนเรียก `GET` — ถ้า state `on` และเลยเวลาปิดรับแผนของพักยกสุดท้าย (หรือไฟต์จบก่อนถึงพักยกนั้น) ให้ `simulate(matchCfg(...)).result` แล้ว `UPDATE matches SET state='done', result=?, reward=? WHERE id=? AND state='on'` (เช็ก `changes === 1` กันสรุปซ้ำ) รางวัลคิดตามข้อ จ. ด้วยการนับแมตช์ `done` ของผู้เล่นคนนั้นในวันเดียวกัน (วันตามเวลาไทย)

ฝั่งเกม (`game.js` ส่วนท้าชก):
- แทน `CH.cdocs`/`CH.adocs` ด้วยรายการจาก `GET /api/match?mine=1` + `?live=1` (ถามทุก 8 วินาที และทุก 2 วินาทีในนาทีสุดท้ายก่อนระฆัง) ให้ `matches()` แปลงแถวเป็นรูปเดิม `{key, from, to, e, a, start, fromName, toName, venue}` เพื่อให้ป้าย รายการ และ `watchMatch` ใช้ต่อได้โดยแก้น้อยที่สุด
- `sendChallenge` `answerChallenge` `cancelChallenge` `quitMatch` `sendRoundPlan` `freshMatch` เปลี่ยนเป็นเรียกเส้นทางข้างบน • `settleMatches`/`applyMatch` ใช้ `result` และ `reward` จากเซิร์ฟเวอร์ ห้ามคำนวณผลเองเพื่อบันทึก
- ตอนขึ้นเวที ถ้า `sim` ของแมตช์ไม่ตรงกับ `SIM_VERSION` ในเครื่อง ให้ `checkBuild()` แล้วโหลดใหม่ • ลบ heartbeat/ลายนิ้วมือในเอกสารคำท้า (`beat` `fightPrint` `theirBeat`) ใช้สถานะออนไลน์จาก `board` อย่างเดียว
- เพิ่ม `get/post` สำหรับ `/api/match` ใน `netdb.js` (คืนผ่าน runtime เช่น `rt.match`) • หน้า artifact: ซ่อนส่วนท้าชก บอกให้เล่นที่เว็บ (ข้อ ง.)
- รุ่นถัดไปหลังยืนยันว่าใช้ได้: เอา `challenges` `answers` ออกจาก `SHARED` แล้วลบแถวเก่า

ทดสอบที่ต้องมี
- `tools/server-test.mjs` (ยิง API บนเว็บจำลองด้วย `fetch` ไม่ต้องเปิดเบราว์เซอร์): ก่อนระฆังขอ `GET` ด้วยกุญแจของอีกฝ่าย **ต้องไม่มี** `seed` และแผนของคู่แข่ง • ตอบหลัง `until` ได้ 409 • ถอนตัวหลังเส้นตายได้ 409 • ส่งแผนนอกช่วงพักยกได้ 409 • คนนอกเรียกเส้นทางเขียนได้ 403 • เรียก `GET` พร้อมกัน 5 ครั้งตอนสรุปผล ได้ผลเดียวและรางวัลชุดเดียว • เกินเพดานรางวัลแล้ว `reward` เป็นศูนย์
- ปรับ `tools/e2e/challenge-flow.mjs` และ `live-fight.mjs` ให้ผ่านกับระบบใหม่ (ลำดับเหตุการณ์เดิมทุกข้อ รวมถอนตัวบนหน้านับถอยหลัง) แล้วรันบนเว็บจริงพร้อม `CLEAN=1` (เพิ่มการลบแถว `matches` ของผู้เล่นทดสอบในสคริปต์)
- ผ่านเมื่อ: ทั้งหมดข้างบนผ่าน • สองจอได้เวที แต้ม ผลเดียวกัน • ไม่มี error ใน `logs` • เจ้าของเกมลองคอมกับมือถือจริงแล้วยืนยัน

ความเสี่ยงที่เหลือหลัง P1 (เขียนไว้ใน `STATUS.md` ด้วย): ค่าพลังยังมาจากเซฟในเครื่อง (ปิดใน P2) • คู่ชกรู้เมล็ดสุ่มหลังระฆัง จึงคำนวณหาแผนยกถัดไปที่ดีที่สุดได้ (ปิดด้วยข้อ ฉ.)

### P1b เมล็ดสุ่มรายยก — หลังเจ้าของเกมตอบข้อ ฉ.

`simulate` รับ `roundSeeds: [s1, s2, s3]` ตั้งตัวสุ่มใหม่ตอนเริ่มแต่ละยก เซิร์ฟเวอร์เปิดเผย `s2` `s3` เมื่อยกนั้นเริ่ม • เป็นการแก้ตัวจำลอง: เพิ่ม `SIM_VERSION` รัน 2,000 ไฟต์เทียบเป้า `npm test` และตัวตรวจคำพากย์ • ไฟต์ที่ไม่ส่ง `roundSeeds` ต้องได้ผลเหมือนเดิมทุกตัว (ไฟต์ปกติและไฟต์ย้อนหลังไม่เปลี่ยน)

### P2 เซิร์ฟเวอร์ถือข้อมูลผู้เล่น — งานใหญ่ แบ่งสามส่วน เขียนแบบสั้นลง `STATUS.md` ให้เจ้าของเกมดูก่อนลงมือแต่ละส่วน

- **P2a อันดับ (RP) มาจากเซิร์ฟเวอร์เท่านั้น**: ไฟต์จัดอันดับจำลองที่เซิร์ฟเวอร์ `POST /api/fight/ranked {plan}` เซิร์ฟเวอร์เลือกคู่ชกเอง (ย้าย `GHOSTS` `makeOpp` `makeStats` `ghostTotal` `rankedOpp` และรายชื่อที่ใช้ ออกจาก `game.js` ไป `src/roster.js` ที่ไม่อ้าง `API`/`S`) สุ่มเมล็ดเอง คืน `{seed, specs, plans, sim}` ให้เครื่องเล่นภาพ แล้วเซิร์ฟเวอร์เขียน `rp` `w` `l` ลง `board` เอง • ผู้เล่นเขียน `board` ของตัวเองได้เฉพาะ ชื่อ ชุด `seen` `in` (ตรวจฟิลด์ในเซิร์ฟเวอร์) • พักยกส่งแผนแบบเดียวกับ P1 แต่ไม่มีเส้นตายเวลา
- **P2b เซฟผ่านด่านตรวจ**: `PUT` ของ `data/users/<id>/save` เทียบกับเซฟก่อนหน้าบนเซิร์ฟเวอร์ ปฏิเสธถ้าเกินกติกา: `day` ลดลงหรือกระโดด • เงินเพิ่มเกินรายได้สูงสุดต่อวันเกม × จำนวนวันที่เพิ่ม • ค่าพลังเพิ่มเกินที่ซ้อมได้สูงสุดต่อวัน (สูตรใน `trainResult`) หรือเกินเพดาน `cap()` • เข็มขัดและของที่ไม่มีทางได้ • เขียนขอบเขตเป็นค่าใน `data.js` และทดสอบด้วยเซฟจากการเล่นจริงของบอท (`autoDay`) 200 วันว่าไม่ถูกปฏิเสธผิด • ค่าพลังที่ใช้ใน P1/P2a อ่านจากเซฟบนเซิร์ฟเวอร์ ไม่รับจากเครื่อง
- **P2c จังหวะเวลาจริง** ตามคำตอบข้อ ข.: เซิร์ฟเวอร์นับวันเกมที่ใช้ได้จากนาฬิกาเซิร์ฟเวอร์ ปุ่มนอนขอวันใหม่จากเซิร์ฟเวอร์
- ข้อควรระวัง: `game.js` ใช้ `Math.random()` 14 จุด (ส่วนใหญ่อยู่ในกติกาซ้อมและอารมณ์) ด่านตรวจใน P2b จึงตรวจ "ขอบเขต" ไม่ใช่เล่นซ้ำทีละคำสั่ง ถ้าวันหนึ่งต้องการเล่นซ้ำแบบเป๊ะ ต้องเปลี่ยนเป็นตัวสุ่มมีค่าตั้งต้นก่อน (งานแยก)

### P3 บัญชี
รหัสย้ายเครื่อง: `POST /api/transfer` ออกรหัส 8 ตัว อายุ 10 นาที ผูกกับ id • เครื่องใหม่ `POST /api/transfer/claim {code}` ได้กุญแจใหม่ กุญแจเก่าใช้ไม่ได้ • ลบบัญชี `DELETE /api/me` ลบทุกแถวของ id นั้น (สโตร์บังคับ) • Cloudflare Turnstile ตอน `register` (ต้องให้เจ้าของเกมสร้าง site key) • จำกัดความถี่คำขอต่อ id ต่อนาที • หน้าตั้งค่าในเกมมีปุ่มทั้งสอง

### P4 พร้อมเปิดสาธารณะ
หน้านโยบายความเป็นส่วนตัวและข้อตกลง (ไทย) • สำรอง D1 (`wrangler d1 export` รายสัปดาห์ เก็บนอก repo) • ตรวจ `logs` และแจ้งเตือน • ทดสอบโหลด (`tools/server-test.mjs` โหมดยิงพร้อมกัน 50 ผู้เล่น) • ไล่สิทธิ์สื่อทุกชิ้นใน `CREDITS.md` (เพลงบนเวที 2 เพลงยังไม่รู้ที่มา • เงื่อนไขเชิงพาณิชย์ของเสียงพากย์ ดนตรี โมเดล ภาพ ที่สร้างด้วย AI) • ลดขนาดโหลดครั้งแรก

### P5 เงินจริง — เริ่มเมื่อเจ้าของเกมเลือกวิธีใน `docs/ONLINE_STORE_PLAN.md` ข้อ 7 เท่านั้น
ของที่ซื้อด้วยเงินจริงและกระเป๋าของมันต้องอยู่บนเซิร์ฟเวอร์ทั้งหมด (ไม่อยู่ในเซฟ) ตรวจใบเสร็จที่เซิร์ฟเวอร์ ขายเฉพาะของแต่งตัวและความสะดวก ห้ามกล่องสุ่มและการพนัน

## 5. งานเสริมที่รอเจ้าของเกมเลือก (ไม่ขึ้นกับเฟสข้างบน)

ผู้ชมไม่ต้องสร้างนักมวย (เปิดลิงก์ `?watch=` แล้วดูได้เลย) • ผู้ชมกดเชียร์ • โทษของการถอนตัวบ่อย • ปุ่มยอมแพ้ระหว่างชก • แจ้งเตือนนอกเกม (ต้องเป็น PWA/แอป) • คำพากย์ของเหตุการณ์ใหม่ (ออกจากเชือก มอบเข็มขัด) ต้องมีกุญแจ Gemini จากเจ้าของเกมผ่านช่องทางที่ปลอดภัย

## 6. ห้ามทำ

- ห้ามขอหรือวาง token รหัสผ่าน กุญแจ ในแชตหรือใน repo

- ห้ามใส่ `Math.random`/`Date.now` ในตัวจำลอง ห้ามให้ตัวเล่นภาพตัดสินผล

- ห้ามสร้าง pull request เว้นแต่เจ้าของเกมขอ
